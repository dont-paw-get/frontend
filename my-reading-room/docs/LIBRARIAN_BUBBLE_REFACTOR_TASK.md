# 작업 지시서: 사서 말풍선/추천 등록 UI 정리 (방향 A)

## 배경

`223b1df feat(register): 추천 도서 바로 등록 및 도서 등록 페이지 필드 자동 완성 기능 추가` 커밋 이후,
사서 답변에서 추천 도서를 추출해 [등록 ➔] 버튼을 노출하는 기능이 **두 곳에 중복 구현**되어 있음을 발견했다.

1. `src/features/room/LibrarianCursor.jsx` — 마우스를 따라다니는 사서 캐릭터 위 말풍선
2. `src/features/room/LibrarianChat.jsx` — 우측 하단 고정 채팅 패널

두 컴포넌트가 각각 `extractBooksFromAnswer(answer.text)`를 호출해서 동일한 추천 카드 목록 + [등록 ➔] 버튼을
따로 렌더링하고 있다. 실제 백엔드 응답을 붙여서 테스트해보니(스크린샷 기준) 아래 두 가지 문제가 확인됐다.

### 문제 1 (완료, 별도 세션 불필요): `bookExtractor.js` 파서가 실제 백엔드 응답 포맷을 못 읽음

백엔드 실제 응답 포맷:
```
### 📖 화성 일기
- **저자**: 앤디 위어
- **추천 이유**: 화성에서 살아남기 위해...
```

기존 파서에는 `### 헤딩` 패턴이 없어서 `**저자**`, `**추천 이유**` 같은 라벨을 볼드 패턴(`boldRegex`)이
title/author로 잘못 잡아 "저자: 박유리 (추천 이유: 가슴...)" 같은 깨진 카드가 노출됐다.

**이미 수정 완료함** — `src/features/room/bookExtractor.js`에 헤딩+키값 블록을 최우선으로 파싱하는
`headingBlockRegex`를 추가했고, 기존 4개 fallback 패턴(『』, 《》, 볼드, 번호목록)은 헤딩 매칭이 실패할 때만
동작하도록 순서를 정리했다. 부수적으로 발견한 `boldRegex`의 저자 파싱 시 하이픈(`-`)이 안 지워지는 기존
버그도 같이 고쳤다. 아래 케이스로 회귀 테스트 확인됨(node로 직접 import해서 검증):

- 헤딩 포맷(`### 📖 제목` + `- **저자**: 이름`) → title/author 정확히 분리
- `『불편한 편의점』 (김호연)` → 기존대로 정상
- `**아몬드** - 손원평` → author가 `"- 손원평"`이 아닌 `"손원평"`으로 정상화(버그 수정)
- `"1. 달러구트 꿈 백화점 - 이미예\n2. 아몬드 - 손원평"` → 기존대로 정상

이 부분은 이미 처리됐으니 이번 작업에서는 다시 손댈 필요 없음. (혹시 diff 확인이 필요하면
`src/features/room/bookExtractor.js`의 `headingBlockRegex` 관련 로직 참고)

### 문제 2 (이번 작업 대상): 말풍선 UI가 답변이 길어질수록 시인성이 떨어지고, 두 UI가 중복됨

`LibrarianCursor.jsx`의 말풍선은 `width: 250px, maxHeight: 260px` 크기로 **마우스를 따라 움직이는 요소** 위에
떠 있다. 답변이 길어지면(스크린샷 참고 — 도서 3권 추천에 각 추천 이유까지 포함된 마크다운 전체) 이 좁은
말풍선 안에서 스크롤을 해야 하는데, 말풍선 자체가 마우스 이동에 따라 계속 움직이는 상태라 읽기/스크롤이
불편하다. 게다가 우측 하단 고정 패널(`LibrarianChat.jsx`)에도 동일한 전체 답변 텍스트와 동일한 추천 카드
목록 + [등록 ➔] 버튼이 이미 존재해서, 사용자가 같은 정보를 두 군데서 보고 어느 쪽 버튼을 눌러야 할지
혼란스러운 상황이다.

## 결정된 방향 (방향 A)

레포가 "귀여운 동물 사서가 큐레이션 해주는" 캐릭터 인터랙션을 컨셉으로 하고 있어서, 마우스를 따라다니는
사서 캐릭터 자체는 유지하되 역할을 분리한다.

- **`LibrarianCursor.jsx`의 말풍선**: 전체 답변 텍스트와 추천 카드/등록 버튼을 모두 제거하고, 짧은 리액션
  문구(1~2줄)만 노출하는 가벼운 말�풍선으로 축소한다. 예: 로딩 중에는 "추천 도서를 찾고 있어요냥... 🐾",
  응답 완료 후에는 "우주 판타지 소설 3권을 찾았어요냥! 아래 채팅창에서 확인해보세요 🐾" 같은 고정 안내
  문구로 대체한다.
- **`LibrarianChat.jsx`의 고정 패널**: 전체 답변 텍스트 렌더링과 추천 카드 목록 + [등록 ➔] 버튼을 그대로
  유지한다(이미 잘 동작하는 구조). 즉, 상세 정보/액션은 여기 한 곳으로 모은다.

## 구현 범위

### 1. `src/features/room/LibrarianCursor.jsx` 수정

- `extractBooksFromAnswer` import 및 `books` 계산 로직 제거 (더 이상 이 컴포넌트에서 도서 추출 불필요)
- `handleRegister` 함수 및 `useNavigate` 관련 코드 제거 (등록 액션이 이 컴포넌트에서 빠지므로)
- 말풍선 내부의 `<div>{answer.text}</div>` — 전체 텍스트 대신 짧은 요약 문구로 교체
  - `answer` prop의 형태를 변경할지, 혹은 이 컴포넌트 내부에서 `answer.text`를 자르는 방식으로 할지는
    아래 "설계 시 고려할 점" 참고해서 결정
- `books.length > 0 && (...)` 추천 카드 블록 전체 제거
- 말풍선 크기(`width: 250, maxHeight: 260`)를 짧은 문구에 맞게 축소 검토 (예: `maxHeight` 제거하고
  고정 1~2줄 높이로, `overflowY: 'auto'`도 더 이상 필요 없어질 가능성 있음)
- 기존 `pointerEvents: 'auto'`는 유지(짧은 문구라도 클릭 영역 방해 없게)하되, 버튼이 없어지므로 실질적
  의미는 줄어듦 — 필요 없으면 제거해도 무방

### 2. `src/features/room/LibrarianChat.jsx`

- 현재 구조(전체 답변 + 추천 카드 목록 + 등록 버튼)를 그대로 유지. 수정 불필요.

### 3. 말풍선에 넣을 짧은 문구 설계 (구현자가 결정할 부분)

다음 두 가지 접근 중 하나를 선택해서 구현:

**옵션 1**: `LibrarianChat.jsx`가 로딩 중/완료 시 넘기는 `answer` 객체에 짧은 요약용 필드를 추가해서
`LibrarianCursor`는 그 필드만 사용 (예: `answer.summary`). 이 경우 `LibrarianChat.jsx`의
`onAnswer({ text: ... })` 호출부에서 `summary`도 같이 채워줘야 함.

**옵션 2**: `LibrarianCursor.jsx` 내부에서 `answer.text`를 기반으로 간단한 규칙(예: 첫 줄만 추출, 또는
글자 수 제한 후 "..." 처리)으로 요약 문구를 만듦. 백엔드 응답 형식이 바뀌어도 대응 로직이 이 컴포넌트에만
있어서 옵션 1보다 결합도가 낮음.

옵션 2를 권장하되, 로딩 중 상태("추천 도서를 찾고 있어요냥... 🐾")는 `LibrarianChat.jsx`가 이미
`onAnswer({ text: ... })`로 넘기고 있는 로딩 placeholder 텍스트를 그대로 짧게 보여주면 되므로 특별 처리 불필요.
완료된 답변에 대해서만 "첫 줄 + 도서 n권 찾음" 같은 요약이 필요.

## 확인 필요 사항 (구현 전 확인)

- `LibrarianChat.jsx`가 `onAnswer`를 호출하는 지점(로딩 시작, 스트리밍 중, 완료 시)이 몇 군데인지 확인하고,
  완료 시점을 어떻게 판별하는지 참고할 것 (`loading` state 기준으로 보임).
- `LibrarianCursor`는 `RoomPage` 등 상위 컴포넌트에서 `answer` prop을 받는 구조이므로, prop 형태를 바꾸면
  상위 컴포넌트도 같이 확인해야 함 (`grep -r "LibrarianCursor" src/` 로 사용처 파악).

## 완료 기준 (Acceptance Criteria)

1. 마우스를 따라다니는 사서 말풍선에는 전체 답변 텍스트나 추천 도서 카드/등록 버튼이 더 이상 노출되지 않고,
   짧은 리액션 문구만 보인다.
2. 답변이 길어져도(도서 3권 + 추천 이유 포함) 말풍선 크기가 커지거나 내부 스크롤이 필요하지 않다.
3. 추천 도서 확인과 [등록 ➔] 액션은 우측 하단 고정 채팅 패널(`LibrarianChat.jsx`)에서만 가능하며, 기존
   동작(클릭 시 `/register`로 이동, 필드 자동완성)은 그대로 유지된다.
4. `npm run dev`로 로컬 실행 후, recommend 모드에서 백엔드 fallback(로컬 chatEngine) 또는 실제 백엔드
   응답으로 테스트했을 때 위 1~3이 육안으로 확인된다.
